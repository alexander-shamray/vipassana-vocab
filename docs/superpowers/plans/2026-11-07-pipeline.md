# Vipassana Vocab — пайплайн данных на Python: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Из плейлиста бесед получить `dictionary/words.jsonl` (в git), `data/examples.jsonl` (в приватный R2) и mp3 произношений (в публичный R2).

**Architecture:** Пакет `vv_pipeline` с подкомандами CLI, каждая читает и пишет файлы в `data/` и кэширует результат — шаги можно перезапускать по отдельности. Чистая логика (фильтр отрезков, леммы, выбор примеров, сборка) отделена от внешних сервисов (YouTube, Whisper, Claude, Azure, R2) и покрыта тестами без сети.

**Tech Stack:** Python ≥ 3.12, `yt-dlp`, `faster-whisper` (large-v3, CUDA), `spacy` + `en_core_web_sm`, `anthropic`, `httpx`, `pyyaml`, `boto3`; разработка — `pytest`, `ruff`.

**Spec:** `docs/superpowers/specs/2026-11-07-vipassana-vocab-design.md`

## Отступления при реализации (2026-11-07)

- **Модель перевода — `claude-opus-5-5`**, а не Sonnet: это модель по умолчанию в актуальной справке по API; ответ по JSON-схеме вместо разбора свободного текста; при отказе — серверный `fallbacks: "default"`.
- **spaCy не нужен в CI**: извлечение лемм принимает анализатор как параметр; тесты используют простой поддельный.
- **Термины Дхаммы и пали сохраняют примеры** даже если входят в 2% самых частых слов — именно их важнее всего услышать в контексте; слово, сказанное один раз, никогда не считается частым.
- **Перевод терминов всегда берётся из глоссария** при сборке, даже без шага `translate`.
- **IPA для пали выводится из написания** (`glossary.pali_ipa`), поле `ipa` в YAML — только для исправлений.

## Отступления после первого запуска на беседах (2026-11-07)

- **Язык по отрезкам больше не определяется.** На беседах 1–2 `detect_language` путал английскую речь с бенгальским, санскритом и тибетским: старое правило выбросило 111 отрезков из 1284 (8,6%), и все они — английская речь. Пения на хинди в расшифровке не оказалось — его вырезает VAD (6,5 мин из 76 в беседе 2). Правило `segments.keep`: `avg_logprob ≥ -1.0`; тишина — только при `no_speech_prob > 0.6` **и** `avg_logprob < -0.5` (faster-whisper сам выкидывает такие отрезки только при `< -1.0`) или при `no_speech_prob > 0.9`; текст не латиницей отбрасывается.
- **Озвучка по умолчанию — Kokoro-82M на своей видеокарте** (решение владельца: Kokoro для локального сайта, Azure — в перспективе). Английский — `bm_george`, пали — голос хинди `hm_omega` по IPA (`ʱ` → `ʰ`). Azure остаётся за флагом `--tts azure`. Имя mp3 — хэш «движок + голос + произносимое».
- **`server dev` раздаёт `data/audio_tts/` по `/audio/`**, если папка есть и `AUDIO_BASE_URL` не задан.
- **Окружение:** PyAV закреплён `<15` (faster-whisper 1.2 передаёт `metadata_errors`, которого в PyAV 19 нет); cuBLAS и cuDNN 9 ставятся из pip, `transcribe.use_pip_cuda` добавляет их в `PATH` на Windows.

## Global Constraints

- Всё под `pipeline/`; рабочие данные — `data/` в корне репо (в `.gitignore`); в git попадают только `dictionary/words.jsonl`, `pipeline/glossary/*.yaml`, `pipeline/overrides/*.yaml`.
- Полные транскрипты и аудио не публикуются никуда.
- Ключ слова — та же нормализация, что в Go: общие кейсы `testdata/fold_cases.json`.
- Примеры: не больше 3 на слово, фраза ≤ 25 слов, из разных бесед, если возможно; у стоп-слов spaCy и верхних 2% по частоте примеров нет.
- Отрезки с `avg_logprob < -1.0`, тишина (`no_speech_prob > 0.6` при `avg_logprob < -0.5`) и текст не латиницей выбрасываются; язык по отрезкам не определяется (см. отступления). Пороги — константы в `segments.py`.
- Перевод: модель `claude-opus-5-5` (`effort: low`, JSON-схема через `output_config.format`, `fallbacks: "default"`), 1–3 русских значения, порции по 40 лемм, кэш `data/translations.json` по ключу.
- TTS по умолчанию: Kokoro-82M локально (`--tts kokoro`); альтернатива — Azure Speech REST (`--tts azure`), формат `audio-24khz-48kbitrate-mono-mp3`; английские слова — голос `en-GB-RyanNeural`, пали — `en-IN-PrabhatNeural` с `<phoneme alphabet="ipa" ph="…">` из глоссария.
- Секреты из окружения: `ANTHROPIC_API_KEY`, `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_PUBLIC_BUCKET`, `R2_PRIVATE_BUCKET`.
- Проверка на Python 3.12: `py -3.12 -m pytest`.

## Review Focus

- Whisper пишет термин пали по-английски с ошибкой (`anichcha`, `vipasana`) → слово привязывается к записи глоссария через её `variants`, а не становится отдельной леммой (Task 3).
- Апостроф и дефис: `don't`, `mind-and-matter`, `“Bhavatu`, кавычки-ёлочки → токены очищены, пустые не попадают в словарь (Task 3).
- Перезапуск перевода после сбоя на середине → уже переведённые порции не отправляются повторно (Task 5).
- Ответ модели с лишним текстом вокруг JSON или с пропущенным ключом → порция повторяется один раз, затем ключ помечается непереведённым, а не роняет весь прогон (Task 5).
- Слово из `overrides` с `drop: true` → нет ни в `words.jsonl`, ни в примерах, ни в TTS (Task 7).
