# Запуск на своей машине и проверка устных игр

Инструкция для Windows, macOS и Linux. На запуск нужно около 5 минут, на
проверку игр ещё 5–10.

## 1. Что нужно установить

| Что | Зачем | Как проверить |
|---|---|---|
| Go 1.27 или новее | собрать и запустить сайт | `go version` |
| Git | забрать код | `git --version` |
| Chrome, Edge или Safari | распознавание речи в устных играх | — |
| Микрофон и интернет | Chrome отправляет звук на распознавание в Google, Edge — в Microsoft | — |

В Firefox распознавания речи нет. Устные игры там откроются, но отвечать
придётся текстом.

## 2. Запуск

```bash
git clone https://github.com/alexander-shamray/vipassana-vocab.git
cd vipassana-vocab/app
go run ./cmd/server dev
```

Первый запуск скачивает зависимости, это около минуты. Сайт готов, когда в
консоли появится строка `listening addr=127.0.0.1:8080`.

Откройте <http://localhost:8080>, нажмите «Войти», затем «Войти локально (dev)».

Что делает режим `dev`:

- Берёт отдельную базу `app/data/dev.sqlite` и не трогает настоящую.
- Загружает 30 тестовых слов из `app/testdata/`. Если конвейер уже собрал
  `dictionary/words.jsonl`, загружает его.
- Включает вход одной кнопкой без Google и GitHub. Такой вход работает только
  на `localhost`, на сервере его нет.
- Слушает только `127.0.0.1`, поэтому с других устройств в сети сайт не
  открыть.

Чтобы остановить сайт, нажмите `Ctrl+C`. Чтобы начать с чистого листа (сбросить
пометки «выучено» и «важное»), остановите сайт и удалите `app/data/dev.sqlite*`.

Другой порт, если 8080 занят:

```bash
PORT=8090 BASE_URL=http://localhost:8090 go run ./cmd/server dev
```

В PowerShell то же самое:

```powershell
$env:PORT = "8090"; $env:BASE_URL = "http://localhost:8090"; go run ./cmd/server dev
```

## 3. Проверка устных игр с микрофоном

Браузер даёт сайту микрофон только по HTTPS или на `localhost`, поэтому
открывайте именно `http://localhost:8080`, а не `127.0.0.1` или IP-адрес.
Если конвейер уже озвучил слова (`data/audio_tts/` есть), `dev` раздаёт эти mp3
сам и сайт играет их. Иначе слова произносит голос браузера.

### «Слушайте и переводите»: английский → русский

1. Откройте «Игры», затем «Слушайте и переводите», нажмите «Начать».
2. Браузер спросит доступ к микрофону, разрешите.
3. Сайт произносит английское слово, статус меняется на «🎤 Говорите…».
4. Скажите перевод по-русски, например «ощущение».

Что проверить:

- [ ] Слово звучит по-английски, а не по-русски.
- [ ] Микрофон включается только после того, как сайт договорил.
- [ ] Правильный ответ даёт зелёное «✓ Верно», неправильный — красное «✗» с
      правильным ответом.
- [ ] «🔁 Повторить» произносит слово ещё раз и снова слушает.
- [ ] «Не знаю» засчитывает ошибку и показывает ответ.
- [ ] Если промолчать, появляется «Ничего не слышно — нажмите „Повторить“ или
      „Не знаю“», и ошибка не засчитывается.
- [ ] После 10 слов показан счёт и список красных слов. Клик по красному слову
      заменяет его на «★ … — в „Важных“».
- [ ] Это слово появилось на вкладке «Важные».

### «Скажите по-английски»: русский → английский

То же самое, но сайт произносит русское значение, а вы отвечаете по-английски.
Дополнительно проверьте:

- [ ] Русский текст звучит русским голосом.
- [ ] Ответ во множественном числе («sensations») засчитывается.
- [ ] Длинное значение произносится целиком, а микрофон включается после него.

### «Напишите перевод»

Микрофон здесь не нужен. Впишите переводы, нажмите «Проверить», кликните по
красному слову: оно уйдёт в «Важные».

### Отказ микрофона

Запретите микрофон: значок замка слева от адреса, «Микрофон», «Блокировать».
Обновите страницу и начните игру.

- [ ] Появляется «Микрофон недоступен… — отвечайте текстом» и поле ввода.
- [ ] Ответ, введённый текстом, проверяется как обычно.

## 4. Проверка с телефона

`dev` слушает только этот компьютер, а с IP-адреса в сети браузер микрофон не
даст. Поэтому:

- **Android и Chrome.** Подключите телефон по USB, включите на нём отладку по
  USB. На компьютере откройте `chrome://inspect/#devices`, затем
  «Port forwarding…», и добавьте правило `8080` → `localhost:8080`. Теперь
  <http://localhost:8080> открывается в Chrome на телефоне, и микрофон там
  работает.
- **iPhone.** Простого способа нет. Проверьте после деплоя: на сервере сайт
  работает по HTTPS.

На узком экране проверьте, что кнопки не вылезают за край, а вкладки
помещаются в одну строку.

## 5. Если что-то не так

| Признак | Причина и что делать |
|---|---|
| `go: command not found` | Go не установлен или его нет в `PATH`. Установите с <https://go.dev/dl/> и откройте новый терминал. |
| `address already in use` | Порт 8080 занят. Запустите на другом порту (раздел 2). |
| Сразу «Этот браузер не распознаёт речь» | Это Firefox. Откройте Chrome, Edge или Safari. |
| «Микрофон недоступен», хотя доступ разрешён | В Windows: «Параметры», «Конфиденциальность», «Микрофон», включите доступ для приложений. В macOS: «Системные настройки», «Конфиденциальность», «Микрофон», включите для браузера. |
| «Микрофон недоступен» при `network` | Нет интернета или Google и Microsoft недоступны: распознавание работает через их серверы. |
| Слово произносится не тем языком или не звучит | В системе нет голоса для этого языка. Chrome обычно приносит свои голоса Google. В Windows русский голос добавляется в «Параметры», «Время и язык», «Речь». Через несколько секунд (чем длиннее текст, тем дольше) игра всё равно перейдёт к ответу. |
| Распознаётся не то, что сказано | Говорите после «🎤 Говорите…» и чуть ближе к микрофону. Сайт проверяет до пяти вариантов распознавания и прощает одну-две опечатки. |
| Новый CSS или JS не подхватился | Такого быть не должно: адреса файлов меняются вместе с содержимым. Если всё же случилось, обновите страницу с `Ctrl+Shift+R`. |

Нашли ошибку — заведите задачу в
<https://github.com/alexander-shamray/vipassana-vocab/issues>: что делали,
браузер и устройство, что увидели.
